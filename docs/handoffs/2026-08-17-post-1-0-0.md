## Open

- **Neither consumer is on `1.0.0`.** `^0.4.0` does not admit it. Both need a hand
  bump — that is the deliberate opt-in the major is for, not an oversight.
- **`uxlab` production still serves no security headers**, open since §10.5 and
  still the only finding with a live effect. It is also four minors behind. Its
  adoption is the same three steps as
  [nuxt-kickstart#15](https://github.com/victortolbert/nuxt-kickstart/pull/15),
  **plus `MD041: false`** locally or it loses a clean markdownlint run.
- **The presets are untested outside the original pair.** ADR-0016 established the
  *mechanism* handles partially-adopted repos; it adopted none, so nothing tests
  whether the *presets* fit a repo that was not one of the two they were measured
  from. `cwds` and `ams-cloud-eds` are the two real candidates. This is
  [ADR-0010](../adr/0010-the-version-contract.md)'s outstanding wish, not a defect.
- **`aem-eds` and `eds-block-lab` are a named non-goal**, not an oversight — active,
  npm-based, no Vue, most presets inert. Taking them up is its own question and
  would be the first test of Preflight under npm.
- **SPEC §11's last item: whether the source template survives** — rebased onto
  Preflight, or retired. A question about `nuxt-kickstart`'s fate, not this
  package's interface, which is why ADR-0010 declined to gate on it.
- **No GitHub Releases exist**, for any of the nine tags. `CHANGELOG.md` now covers

## How to work here

- **Releases are cut deliberately, never automatically.** They publish to a public
  registry and npm never reissues a version number, so the decision to release is
  the maintainer's. When something is release-ready, say so and name the version
  and the command rather than running it unasked.
- **Test adoption by copying a real repo's files into a scratch directory** and
  running the built CLI against them, rather than reasoning about what would
  happen. That is what found the only defect in the whole migration item, and it
  takes about a minute. Do it before making any claim about what adoption costs.
- **Use the session scratchpad for working files, not `/tmp`.** The previous two
  sessions left ~40 spent `.out`/`.txt` files there, which had to be cleaned up by
  hand and made the genuinely useful files hard to pick out.

## Gotchas from this session

The repo handoff this replaces still has good ones; these are new, and none are
recorded in an ADR.

- **`markdownlint-cli --config` takes a file path, not inline JSON.** Passing
  `--config '{"MD049":…}'` prints `Cannot read or parse config file` **and then
  silently falls back to the discovered `.markdownlint.json`** — so two different
  invocations returned byte-identical results and the measurement looked
  conclusive. Write a temp config file. (ADR-0013's method note records the
  adjacent trap: `--config` *merges* with a discovered config per key.)
- **`markdownlint --fix` is destructive on continued ordered lists**, exits `0`
  doing it, and would have silently renumbered SPEC §10's items 9 and 10 —
  breaking every `§10.9` citation across three ADRs and two handoffs. Recorded in
  [ADR-0013's addendum](../adr/0013-markdownlint-ships-seven-rules-as-json-via-extends.md);
  the general lesson is that *auto-fixable* is not *safe to auto-fix*.
- **`npm pack --dry-run --json` is not parseable here.** `prepack` runs the build,
  whose output precedes the JSON, and stripping to the first `[` still does not
  yield valid JSON. Use the human-readable form and grep it.
- **Releasing is `pnpm exec bumpp <version> --yes`** — the form
  [`docs/releasing.md`](../releasing.md) documents. `pnpm run release -- <v> --yes`
  drops the flags and hangs on a prompt with no terminal to answer it.
- **Verify exit codes directly.** `cmd | tail` reports `tail`'s status; this bit
  once again this session, on a `markdownlint` run that looked clean because
  `wc -l` was counting pnpm's banner line.

## Method note

SPEC §10's closing finding — *every entry described a file, and every entry was
written by someone who had not opened it* — held for §11 too. It said "several
projects carry a subset of the tooling" and counted nothing; counting found 8
repos, of which **2** are real candidates and 4 are not candidates at all.

It also produced the session's most useful measurement, which was a
**disconfirmation**: not one of those 8 matches what Preflight ships on any file
it carries, so zero would land in `unrecorded`. Adoption was a no-op in the two
consuming repos *by construction* — a property of how they were chosen, not of
the package. Any claim starting "adoption is cheap because" should be checked
against that.

Two claims were nearly asserted from memory this session and were wrong on
checking: that `taze` was dead config here (it is a peer dependency for authoring
the preset), and that `changelogithub` was already wired up here (it is
`nuxt-kickstart`'s). Both would have shipped as findings. **Check before
asserting, including — especially — about this repo.**
